# Задачи по сайту ALAS — для следующего исполнителя

Проект уже собран и работает: Next.js 16 (App Router), Tailwind v4, Motion, Lenis.
Главная страница из 11 секций, рабочий калькулятор на реальных тарифах, сквозной WhatsApp-слой.
Дизайн-система, копирайтинг и правила съёмки — в `docs/alas-frontend-spec.md`.
Обзор проекта и что осталось подставить — в `README.md`.

Задачи ниже отсортированы по приоритету. Берите по одной, не смешивайте в одном подходе.

---

## Правила, которые нельзя нарушать

1. **Дизайн-систему не переписывать.** Все цвета, радиусы, тени и кривые анимаций лежат в
   `src/app/globals.css` в блоке `@theme`. Использовать только эти токены и готовые классы
   (`.btn`, `.surface`, `.glass`, `.shell`, `.eyebrow`, `.h1`, `.h2`, `.h3`, `.muted`, `.nums`,
   `.hairline`, `.media-frame`). Новые цвета и радиусы не вводить.
2. **Никаких стоковых фото и видео.** Ни Unsplash, ни Pinterest, ни ИИ-генерации интерьеров.
   Если своего материала нет — оставить компонент `MediaSlot` с текстовым ТЗ на кадр. Это
   осознанное решение: сток уничтожает позиционирование.
3. **Цены не хардкодить.** Источник истины — `src/lib/pricing.ts`. Если цифра нужна в вёрстке,
   импортировать её оттуда. То же с контактами: только `src/lib/contact.ts`, номер
   `8 707 306 75 76` нигде не дублируется строкой.
4. **Ссылки на WhatsApp — только через `waLink(source, text)`** из `src/lib/contact.ts`.
   Прямые `https://wa.me/...` в JSX запрещены: теряется разбивка по источникам в аналитике.
5. **Ничего не выдумывать в социальных доказательствах.** Отзывы, рейтинги, количество уборок,
   цены кейсов — только реальные данные от владельца. Придуманный рейтинг = обман клиента.
6. **Не добавлять UI-библиотеки** (MUI, shadcn, Bootstrap, Ant). Вёрстка ручная на Tailwind.
7. **Анимации только на `transform`, `opacity`, `filter`** и всегда с проверкой
   `useReducedMotion()`. Никаких анимаций `height`, `top`, `box-shadow` в кадре.
8. **Тексты на русском — без канцелярита и без «мы команда профессионалов».** Тон задан в
   существующих секциях, держаться его.

## Как проверять себя после каждой задачи

```bash
npm run typecheck   # должно быть пусто
npm run lint        # должно быть пусто
npm run build       # должно собраться без ошибок
npm run dev         # глазами проверить главную и /dev/type
```

Если правили шрифты — дополнительно `npm run fonts:check`: у шрифта обязан быть подсет
`cyrillic-ext`, иначе казахские Ә Ғ Қ Ң Ө Ү Һ ломаются.

## P0 — до публикации сайта

### Задача 1. Техническая база метаданных

**Файлы:** создать `src/app/icon.svg`, `src/app/apple-icon.png`, `src/app/opengraph-image.tsx`,
`src/app/robots.ts`, `src/app/sitemap.ts`, `src/app/not-found.tsx`; правки в `src/app/layout.tsx`.

Что сделать:

- Иконка сайта: монограмма `A` или слово `ALAS` шрифтом Playfair, цвет `--color-linen` на фоне
  `--color-obsidian`, с точкой-искрой `--color-ember-500`. SVG, без внешних зависимостей.
- `opengraph-image.tsx` через `ImageResponse` (1200×630): обсидиановый фон, заголовок
  «Чистота и обряд Аластау», подпись «Премиальный клининг · Алматы», номер телефона из `CONTACT`.
- В `layout.tsx` добавить `metadataBase: new URL(process.env.NEXT_PUBLIC_SITE_URL ?? "http://localhost:3000")`,
  `alternates.canonical`, и второй `themeColor` для тёмной схемы (`#14120f`).
- `robots.ts`: разрешить всё, кроме `/dev/` и `/admin`, указать sitemap.
- `sitemap.ts`: главная (и позже казахская версия).
- `not-found.tsx`: та же стилистика, заголовок «Такой страницы нет, а чистота — есть»,
  кнопка на главную и кнопка WhatsApp через `WhatsAppButton`.

**Критерии приёмки:** в `<head>` есть og-картинка и canonical; `/robots.txt` и `/sitemap.xml`
отдаются; `/dev/` закрыт от индексации; 404 выглядит как часть сайта, а не как дефолт Next.

### Задача 2. Юридическая часть и реквизиты

**Файлы:** `src/components/layout/SiteFooter.tsx`, создать `src/app/privacy/page.tsx`.

- Взять у владельца: форма (ИП или ТОО), полное наименование, БИН/ИИН, адрес, e-mail.
  Подставить в футер вместо заглушки «БИН/ИИН — указать».
- Страница политики конфиденциальности: какие данные собираем (имя, телефон, адрес),
  зачем (выполнение заказа), сколько храним, как удалить по запросу, кому передаём (никому).
  Ссылка из футера. Текст простой, без юридического шума, но по существу.
- В форме бронирования (`src/components/calculator/BookingForm.tsx`) добавить под кнопкой
  строку согласия со ссылкой на политику.

**Критерии приёмки:** ни одной заглушки в футере; `/privacy` открывается и сверстана в стиле сайта.

### Задача 3. Незакрытые цифры

**Файлы:** `src/lib/pricing.ts`.

- Спросить у владельца цену обряда «Аластау» как отдельной опции при влажной уборке и
  подставить в `ALASTAU_OPTION_PRICE` (сейчас стоит placeholder 9 900 ₸).
- Уточнить, что считается стандартным балконом (сейчас `BALCONY_STANDARD_M2 = 6`).
- Проверить у владельца оценку времени и состава команды в `calculateEstimate` — коэффициенты
  `speedPerHour` и `crew` подобраны на глаз, их надо сверить с реальной практикой.

**Критерии приёмки:** в коде нет комментариев `TODO` про цены; расчёт для 62 м² генеральной даёт
сумму и время, которые владелец подтвердил.

### Задача 4. Деплой

- Залить проект в приватный репозиторий на GitHub, подключить Vercel, задеплоить.
- Переменные окружения на Vercel: `NEXT_PUBLIC_SITE_URL`.
- Подключить домен, включить HTTPS.
- Проверить сайт с реального телефона: работает ли нижний бар с WhatsApp, не перекрывает ли он
  контент, открывается ли чат с предзаполненным текстом.

**Критерии приёмки:** сайт доступен по домену, WhatsApp с телефона открывает чат с текстом,
Lighthouse на мобиле в зелёной зоне по Performance и Accessibility.

## P1 — сразу после запуска

### Задача 5. Аналитика

**Файлы:** `src/app/layout.tsx`, `src/lib/analytics.ts`, `.env.example`.

- Подключить GA4 и Яндекс.Метрику через `next/script` со `strategy="afterInteractive"`,
  ID брать из `NEXT_PUBLIC_GA_ID` и `NEXT_PUBLIC_YM_ID`. Если переменной нет — скрипт не
  рендерится (чтобы локально не мусорить).
- В `track()` добавить отправку в Метрику через `window.ym(id, "reachGoal", event, params)`.
  Функция `track` уже вызывается во всех нужных местах, новые вызовы добавлять не надо.
- В Метрике включить вебвизор и карту скроллинга.
- Настроить цели: `whatsapp_click`, `phone_click`, `calc_start`, `calc_extras_add`,
  `alastau_toggle`, `booking_submit`.

**Критерии приёмки:** в отладчике GA4 и Метрики видно события при клике по WhatsApp и по
тумблерам калькулятора; в событии `whatsapp_click` приходит параметр `source`.

### Задача 6. Казахская версия

**Файлы:** установить `next-intl`; создать `messages/ru.json`, `messages/kz.json`,
`src/i18n/*`; перевести структуру на `src/app/[locale]/`.

- Все русские строки вынести из компонентов в `messages/ru.json`. Готовые строки для части
  секций уже собраны в `docs/alas-frontend-spec.md`, §7 — использовать их, не переписывая.
- `messages/kz.json` — **не машинный перевод**. Особенно секция обряда: там нужен носитель языка.
  Если носителя нет, оставить задачу незакрытой и сказать владельцу, а не заливать Google Translate.
- Переключатель ҚАЗ/РУС в `SiteHeader.tsx` (сейчас там неактивная надпись) — сделать рабочим,
  сохранять выбор в cookie, менять `<html lang>`.
- Добавить `alternates.languages` и hreflang, обновить `sitemap.ts`.
- Тексты WhatsApp-заготовок в `src/lib/contact.ts` тоже локализовать: казахоязычный клиент должен
  писать нам на казахском.

**Критерии приёмки:** `/kz` и `/ru` работают, переключатель не сбрасывает скролл в никуда,
на `/dev/type` все казахские глифы рендерятся тем же шрифтом, что и остальной текст.

### Задача 7. Реальные фото и видео

**Файлы:** `public/media/*`, `src/components/ui/MediaSlot.tsx`,
`src/components/ui/LensCompare.tsx`, `src/components/sections/HeroSection.tsx`.

Делать только когда владелец сдал материал по чек-листу из `docs/alas-frontend-spec.md`, §9.

- `MediaSlot` доработать так, чтобы он принимал `src` и `alt` и рендерил `next/image` с
  `sizes`, а без `src` продолжал показывать ТЗ на кадр. Существующие вызовы не ломать.
- Hero: добавить `<video>` слоем под текстом — `muted`, `loop`, `playsInline`, обязательный
  `poster`, `preload="metadata"`. CSS-сцена остаётся фолбэком, если видео не загрузилось.
  На мобиле видео не грузить: показывать только постер.
- `LensCompare`: заменить два CSS-градиентных слоя на пары `next/image`. Требование к парам —
  один штатив, один объектив, одинаковая экспозиция. Если пары сняты по-разному, вернуть их
  владельцу на пересъёмку: разница должна читаться в чистоте, а не в свете.
- Форматы: AVIF или WebP, длинная сторона не больше 2000 px, видео H.264 до 4 МБ на луп.
- `priority` только на первом изображении Hero, остальное — ленивая загрузка.

**Критерии приёмки:** LCP на мобиле меньше 2.5 с, CLS меньше 0.05, ни одного стокового кадра.

## P2 — когда основное работает

### Задача 8. Firebase: заявки, слоты, контент

**Файлы:** `src/lib/firebase.ts` (создать), `src/app/api/booking/route.ts` (создать),
`src/components/calculator/BookingForm.tsx`, `src/components/sections/HeroSection.tsx`.

- Firestore: коллекции `bookings` (заявки), `slots` (свободные окна), `cases` (кейсы),
  `reviews` (отзывы), `settings` (цены и опции, включая цену обряда).
- Заявка из `BookingForm` уходит в Firestore через server action или API route,
  плюс уведомление владельцу (WhatsApp Business API или Telegram-бот — что дешевле).
- **Критически важно:** кнопка «Подтвердить бронь в WhatsApp» остаётся. Даже если запись в
  Firestore упала, клиент всё равно должен попасть в чат с готовым текстом. Сначала открываем
  WhatsApp, запись делаем параллельно и не блокируем интерфейс ошибкой.
- Свободные слоты в Hero (`3 из 14`) и даты в форме брать из `slots`, а не из константы.
- Цены читать из `settings` с фолбэком на значения из `src/lib/pricing.ts`.
- Простая админка `/admin` за Firebase Auth: список заявок со статусами, редактирование цен,
  публикация кейсов и отзывов. Закрыть от индексации.

**Критерии приёмки:** заявка появляется в Firestore и приходит уведомлением; при выключенном
интернете у Firestore сайт продолжает работать и отправлять клиента в WhatsApp.

### Задача 9. Доступность и производительность

- Прогнать Lighthouse на мобиле, добить Performance и Accessibility до 90+.
- Проверить контраст: `--color-sage-400` на `--color-linen` для текста почти наверняка не
  проходит 4.5:1 — для текста использовать `--color-sage-900` или `--color-sage-600`.
- Пройти сайт клавиатурой: `LensCompare` управляется стрелками (уже реализовано, проверить
  фокус-рамку), все кнопки и тумблеры достигаются табом, у модальных элементов есть выход.
- Включить `prefers-reduced-motion` в системе и убедиться, что скраб дыма, параллакс Hero и
  автоподсказка линзы отключаются, а сайт остаётся читаемым.
- Проверить, что нижний мобильный бар не перекрывает итог сметы и кнопки внутри калькулятора.

### Задача 10. Продуктовые улучшения

- «Аластау без дыма» (гидролат) — сделать отдельным выбором внутри шага 5 калькулятора:
  переключатель «с дымом / без дыма». Сейчас это только упомянуто текстом.
- Добавить в калькулятор поле «Есть питомцы / аллергия» — влияет не на цену, а на протокол
  уборки, и это заметно повышает доверие. Значение передавать в текст заявки.
- Блок вертикальных видеоотзывов (stories-кружки с модалкой) вместо текстовых карточек в
  `SocialProofSection` — когда владелец снимет видео.
- Страница услуги «Уборка после ремонта» отдельным лендингом под SEO-запрос: он самый
  дорогой и самый горячий.
